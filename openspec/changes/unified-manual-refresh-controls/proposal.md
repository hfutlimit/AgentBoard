# Proposal: 统一工作区手动刷新控件

## 问题

提案列表、提案详情和 Story Task 列表都提供手动刷新，但它们各自复制 SVG、spinner、可视文字和状态属性，并共同受通用 `.icon-btn` 的尺寸与内边距影响。既有 `.refresh-btn` 在 hover 时还会旋转图标。结果是标题操作区的尺寸、信息密度、操作优先级和无障碍语义不一致，也会与主操作争夺空间。

## 目标

把三个指定工作区入口收敛为同一种 36px 图标型次级操作，并让既有 Task 工具栏的 `#refreshBtn` 使用同一视觉语言。刷新仍由现有父视图方法执行；API、路由、刷新范围、toast 与并发守卫均保持不变。

## 变更范围

- 新增只负责呈现与事件转发的 Angular 手动刷新按钮组件及其专用样式。
- 将四处手动刷新模板接入该组件：三个指定工作区入口及既有 Task 工具栏 `#refreshBtn`。
- 调整标题操作区和 Story Task 操作区的受限响应式布局；提案详情中的刷新排在派发/重新派发主操作之前。
- 补充组件、三个指定入口和根 Task 工具栏的前端单测，并增加目标 Playwright UI 回归。

## 非目标

- 不修改 `manualRefresh()`、`refreshStoryTasks()`、`refreshProposals()` 或 `refreshProposalDetail()` 的请求、数据范围、错误处理或 toast。
- 不修改自动刷新、筛选、分页、路由、API、后端数据契约或任何非指定刷新文字按钮。
- 不把本次组件变成服务、状态容器或请求发起者。
