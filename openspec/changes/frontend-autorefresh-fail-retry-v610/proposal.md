# Proposal: 后台自动刷新失败提示与一键重试 — Epic 82 v6.10

## 问题
v6.9 已落地后台自动轮询刷新（每 30s 静默 `loadRoute(false)`），失败时仅把同步状态点转为琥珀色 `.failing` 圆点。该指示过于隐蔽：用户不易察觉自动刷新已中断，也无任何可恢复入口——只能关闭再重新开启自动刷新，或被动等待下一个轮询周期重试。

## 目标
在自动刷新处于失败态（`autoRefreshFailing() && autoRefresh()`）时，提供明确且低调（不打扰式）的失败提示与一键重试：
- **失败提示条**：自动刷新按钮旁出现胶囊状提示「自动刷新失败」，含闪烁告警点与文案，与 v6.9 状态点告警色一致（琥珀 `--warning`）。
- **一键重试**：提示条内嵌「重试」按钮，点击立即触发一次静默同步（`retryAutoRefresh()`），并重置倒计时，不弹 toast、不闪骨架屏。
- 重试进行中按钮禁用（与 `refreshing()` 互斥），避免与手动/自动刷新竞态。
- 失败态随下次成功同步自动消失（复用既有 `autoRefreshFailing` 复位逻辑）。

## 范围
- 纯前端，零后端契约变更（复用 `autoRefreshFailing` / `refreshing` / `autoRefresh` 信号与 `autoRefreshTick()`）。
- 不影响 v6.6 手动刷新、v6.7/v6.8 刷新 toast、v6.9 自动轮询的既有行为。

## 非目标
- 不做失败指数退避自动重连（保持 30s 固定周期轮询即可，重试按钮提供即时性）。
- 不做失败原因详情弹层（保持低调，不喧宾夺主）。
