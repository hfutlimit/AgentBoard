# Proposal: 后台自动刷新成功轻提示 — Epic 83 v6.11

## 问题
v6.9 落地了后台自动轮询刷新（每 30s 静默 `loadRoute(false)`），v6.10 又补齐了失败态的「自动刷新失败」提示条 + 一键重试。但成功路径至今完全静默：用户既看不到「自动刷新正在工作」，也看不到「从失败中恢复」。失败有反馈、成功无反馈，体验不对称，且恢复过程缺乏正反馈闭环。

## 目标
为自动刷新成功路径补齐**轻量、不打扰**的正反馈，并与 v6.10 失败提示形成联动：
- **恢复成功 toast**：当自动同步从失败态（`wasFailing`）恢复为成功时，弹出一次「后台已恢复同步」成功 toast（复用既有 toast 基础设施，5s 自动消失）。仅「恢复」时弹，不每个轮询周期弹，避免打扰。
- **同步成功轻提示**：每次自动同步成功时，状态点瞬间点亮绿色并闪烁（`autoSynced` 瞬时标记，1.5s 自动熄灭），按钮旁短暂出现「已同步」胶囊，给用户「后台在持续同步」的可见信号。
- 复用既有 `autoRefreshFailing` / `refreshing` / `autoRefresh` / `lastSyncedAt` 信号，零后端契约变更。

## 范围
- 纯前端，零后端契约变更。
- 不影响 v6.6 手动刷新、v6.7/v6.8 刷新 toast、v6.9 自动轮询、v6.10 失败提示与重试的既有行为。

## 非目标
- 不做每周期成功 toast（避免每 30s 打扰用户），仅「恢复」瞬间给一次成功反馈。
- 不做同步耗时 / 数据变更量统计展示（保持低调）。
