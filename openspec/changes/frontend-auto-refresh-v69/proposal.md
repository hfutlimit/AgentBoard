# Proposal: 任务视图后台自动轮询刷新 (v6.9)

## 问题
v6.6 引入手动刷新按钮、v6.7/v6.8 补齐成功/失败 toast，但视图刷新仍依赖用户主动点击。
在多人协作场景下，他人新建/改状态的任务无法即时反映在当前用户视图中，需频繁手动刷新，
体验割裂。缺少「后台静默轮询」能力。

## 方案
在工具栏手动刷新按钮旁新增「自动」开关，开启后以后台定时器（默认每 30s）静默调用
`loadRoute(false)` 同步最新数据，**保留当前视图不闪骨架屏**。提供：
- 倒计时徽标：距下次自动刷新的秒数；
- 同步状态点：开启时绿色呼吸脉冲，连续失败转琥珀告警（不打扰式 toast，与手动刷新 toast 解耦）；
- 「刚刚同步 / Ns前同步」相对时间提示（title）；
- 偏好持久化 `localStorage.agentboard_auto_refresh`，默认关闭；
- 页面不可见（`document.hidden`）时冻结倒计时，避免无谓请求。

## 范围
- 纯前端，零后端契约变更。
- 复用既有 `refreshing` 信号做手动/自动互斥，避免并发刷新。
- 不改动手动刷新语义（toast 仅在手动触发时弹出）。
