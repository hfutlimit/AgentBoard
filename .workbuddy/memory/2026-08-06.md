- **坑（关键）**：
  1. **COS V5 签名是四步算法**，不是直接对 HttpString 做 HMAC！官方 StringToSign = `sha1\\n{KeyTime}\\n{SHA1(HttpString)}\\n`；SignKey = HMAC-SHA1(SecretKey, KeyTime)；Signature = HMAC-SHA1(SignKey, StringToSign)。初版实现直接对 HttpString 做 HMAC 是错的，搜索官方文档（cloud.tencent.com/document/product/436/7778）后修正。
  2. `urllib.request.Request.headers.items()` 返回的 header 名被 `.capitalize()`：`content-type`→`Content-type`、`authorization`→`Authorization`。测试断言统一小写。
  3. `Authorization` 参数按**字典序**排列（与 cos-python-sdk-v5 SDK 行为一致：sorted(authorization.items(), key=...)）。文档展示顺序是 `q-sign-algorithm&q-ak&...&q-signature`，但**实际字典序**是 `q-ak&q-header-list&q-key-time&q-sign-algorithm&q-sign-time&q-url-param-list&q-signature`（服务端解析后重建，无影响）。
  4. `urllib.parse.parse_qs` 默认 `keep_blank_values=False`，会丢弃 `q-url-param-list=` 这种空值参数。断言需加 `keep_blank_values=True`。
  5. PUT 请求签名 TTL 用 `_REQUEST_TTL_SECONDS=60`（与预签名 86400 不同），不要混用。
  6. **Git Bash 无 `tee`/`seq`/`sleep`** 命令（被 Windows 同名词替换/缺失）→ 用 Python 子进程 `time.sleep` 代替。
  7. **Docker Desktop 启动时所有容器自动恢复**（含 mcp 18001），属环境自动行为而非主动操作；如需避免，单独 `docker compose up -d api` 而非重启整个 compose stack。
