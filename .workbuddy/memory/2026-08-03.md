## 项目文档文件夹功能（Epic 15 增强）
- 需求：文档支持创建文件夹/子文件夹；拖拽文件到子文件夹或面包屑节点归档。
- 后端：新增 `document_folders` 表（project_id + parent_id 自引用 + name，删除子项上提父级），`documents.folder_id` 列（FK SET NULL）。Alembic 迁移 `j6k7l8m9n0a1`（SQLite 用原生 ALTER ADD COLUMN 带 REFERENCES，MariaDB 走 add_column+create_foreign_key——SQLite 的 op.create_foreign_key 会抛 NotImplementedError）。
- API：`/api/document-folders` CRUD + DocumentIn/Patch.folder_id（显式 null = 移出到根，用 `model_fields_set` 判断避免 exclude_none 吞掉）；中间件项目解析 + 审计映射 `document_folder`。
- service：文件夹 CRUD 含防环（`_folder_is_descendant` 沿 parent_id 向上遍历）；`update_document` 对 folder_id 单独分支（null 合法）。
- 前端：面包屑（可点击进入 + 每节点是 drop 目标，根=全部文档）、文件夹卡片（进入/重命名/删除/计数）、新建文档弹窗可选所在文件夹（`docCreateFolderId` 默认当前文件夹）、项目 Tab 与全局视图共用 signals（`docFolders/docFolderId/docFolderModal/docDrag/docDropId`），进入 tab/视图时重置 docFolderId=null。
- ⚠️ 拖拽踩坑（重要）：HTML5 DnD 手动构造 `new DataTransfer()` 派发事件时，drop 阶段 `getData` 不可靠 → 组件 `docDrag` 信号在 dragstart set 后 drop 读取正常（真实浏览器 OK），但自动化 dispatchEvent 场景下失效。**最终方案：payload 三通道**——window 全局 `__agentboardDrag`（首选，dragstart 写 drop 读）→ dataTransfer 自定义 MIME `application/x-agentboard-drag` → 组件信号回退。drop 事件在嵌套 drop 目标（crumb↔nav）间冒泡会触发多次 → `_docDropBusy` 防重入。
- 验证：19 项 TestClient 自测（含防环/跨项目 422/非成员 403/删除上提）+ Playwright E2E 全链路通过（建顶层文件夹→进内建子文件夹→子文件夹内建文档→拖到面包屑移入上级→拖到根）。
- ⚠️ 拖拽延迟现象：页面预加载风暴（侧栏整树 stories/tasks 并发请求，既有性能债）期间拖拽 PATCH 延迟 5-8s；networkidle 后 1.2s。非本功能缺陷。
