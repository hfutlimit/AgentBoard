## 修复 MCP API Key 权限模型（admin key 只见 2 项目问题，commit a60cec8）
- **现象**（用户在生产 Windows 服务器 C:\AgentBoard 复现）：同一 admin key，REST /api/projects 返回 9 个项目，MCP list_projects 只返回 2 个；MCP admin_list_projects 返回 403 "admin only"。
- **三层根因**：① `mcp_server._proj_list` 硬编码调 `/api/users/me/projects`（07-28 防越权改动一刀切，无视 is_admin）；② MCP 服务用固定令牌 `AGENTBOARD_MCP_TOKEN`（mcp-service→testadmin uid=1），`MCP_REQUIRE_AUTH=0` 时调用方 key 不被采纳，返回的 2 个项目其实是 testadmin 的成员项目；③ `/api/admin/*` 4 个端点用 `auth.parse_token()` 鉴权，只认登录 token 不认 `abk_` key → 任何 API key 都 403。
- **修复（权限模型收敛为「API Key 权限 = 关联用户权限」）**：
  - `mcp_server._proj_list`：先调 `/api/auth/me` 判身份，admin → `/api/projects` 全量；普通用户 → `/api/users/me/projects` 成员作用域。防越权的正确边界 = 给 MCP 配非管理员 key，而非在工具层无视 is_admin。
  - `api.py` 新增 `_require_admin(authorization, s, permission=)`（内部走 `_current_user`，同时支持 Bearer token 与 abk_ key；无凭证/无效凭证保持历史行为 403）；`admin_list_users`/`admin_update_user`(api:write)/`admin_list_projects`/`admin_delete_project`(api:write) 全部改用。
  - 回归测试 `tests/test_admin_api_key_scope.py`（TestClient + 内存 SQLite）全绿；`_proj_list` 分流用 ast 提取源码打桩验证（本地 venv 无 fastmcp，不能直接 import mcp_server）。
- **重要事实**：`C:\AgentBoard` 不在本机（Test-Path False）——是生产 Windows 服务器的部署目录。本机已同步 `dist/agentboard-webapi` 与 `dist/agentboard-mcp` 部署包中的 api.py/mcp_server.py 并 push；**生产需 git pull 后覆盖 C:\AgentBoard\webapi 与 C:\AgentBoard\mcp 的对应文件并重启 NSSM 服务**才生效。
