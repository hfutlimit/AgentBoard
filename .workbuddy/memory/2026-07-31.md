## 2026-07-31 自动开发 — Epic 96 P2-0 服务端 CAS 原子认领 + 显式租约 → in_review（达成）

- 目标：Task 933 → in_review（显式终态指令）。这是 Story 156(P2 RabbitMQ) 的硬前置：消灭 Worker 认领 TOCTOU 与「崩溃 Worker 租约被无关写入续期导致永久卡死」两个真实缺陷（P1-2 因「零 REST 契约变更」约束只在客户端 GET+PUT 规避，根治记入 P2）。
- 两个根因：① `set_proposal_status` 同态迁移(analyzing→analyzing)是幂等 no-op 返回 200，PUT 无法仲裁并发，N 个 Worker 全拿 200 重复分析；② 崩溃恢复判定用 `updated_at`（带 onupdate），用户作答/PATCH converged_spec 等无关写入会刷新它，使已崩溃 Worker 租约被无限续期。
- 根治：单条条件 `UPDATE ... WHERE id=? AND status IN ('queued','answered')`，由 DB 仲裁 rowcount（SQLite 写锁串行化 / MariaDB 行锁），恰好 1 赢家 200、其余 409；显式租约字段 `claimed_by`/`claimed_at`（仅认领写入，绝不随无关写入续期）；`reclaim_stale` 依据 `claimed_at`（updated_at 仅兜底迁移前 NULL 行）；`database.py` SQLite 加 `PRAGMA busy_timeout=10000` 让并发认领排队而非报 locked。
- 改动（契约**增量**，非破坏性）：`domains/proposals/models.py`(+claimed_by/claimed_at+CLAIMABLE_STATUSES)、`models.py` facade、`database.py`、`service.py`(+claim_proposal/reclaim_stale_proposals + set_proposal_status 租约维护)、`api.py`(+`POST /claim` + `POST /reclaim-stale`，200/409/404)、`worker.py`/`mcp_server.py`(认领路径切 CAS)、新增迁移 `i5j6k7l8m9n0_add_proposal_claim_lease.py`。
