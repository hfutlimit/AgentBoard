架构设计：认证服务

文档 · 最后编辑 2025-08-20 · 由 韩梅梅

认证服务（Auth Service）是认证重构 Epic 的核心组件，负责统一承接登录、令牌签发与权限校验。本文描述其边界、组件构成与关键时序。

范围说明：本期仅覆盖令牌体系与 RBAC，账户体系（注册 / 改密 / 找回）不在范围内，留待下个 Epic。

组件构成

认证服务由以下子模块组成，均部署于独立命名空间，通过内部 gRPC 互相调用：

· Token Issuer — 签发与校验 JWT，管理密钥轮转；
· Session Store — 维护刷新令牌与设备会话；
· RBAC Engine — 解析角色与权限策略；
· OAuth Gateway — 对接第三方身份提供商。

令牌配置

访问令牌默认有效期 15 分钟，刷新令牌 7 天，密钥每 24 小时轮转一次：

auth:
  token:
    access_ttl: 15m
    refresh_ttl: 7d
    algorithm: RS256
  key_rotation:
    interval: 24h  # 自动轮转，旧密钥保留 1 个周期

登录时序

第三方登录与站内密码登录共用同一会话写入路径，差异仅在令牌来源：

步骤参与方动作
1客户端发起登录（密码 / OAuth 回调）
2Auth Service校验凭据，换取令牌
3Session Store写入刷新令牌与会话
4客户端持有 access_token 访问业务 API

风险与对策

· 令牌泄露：access_token 短时效 + 绑定设备指纹；
· 密钥轮转中断：旧密钥保留一个轮转周期，灰度发布；
· 第三方不可用：提供站内密码登录兜底，避免完全锁定。
