# AgentBoard MCP Agent 工作规范

版本：2026-08-27.1

这份文档是 AgentBoard Worker 调用任何无头 Agent 时的强制前置规范。它适用于需求澄清、工单拆分、Design、开发、QA、Review 和 Review 驳回后的返工。

## 1. 固定执行顺序

1. 先确认当前工作类型、项目、工作项层级、验收标准和历史评论。
2. 先检索并阅读当前项目里的真实代码、配置和测试，再进行分析、提问、设计、修改、测试或评审。
3. 通过已配置的 AgentBoard MCP 获取或更新工作项状态；禁止绕过 MCP 直接访问 AgentBoard 数据库，也禁止猜测服务端状态。
4. 完成工作后执行与风险相匹配的验证，并报告实际证据，不能把计划、静态推断或健康检查冒充完成结果。
5. 最终 JSON 必须包含 `inspected_files`，列出真正读过的、相对项目根目录的文件路径。

## 2. 代码阅读底线

- 使用当前环境可用的仓库工具检索文件和符号，例如 `rg --files`、`rg`、目录浏览和文件读取工具。
- 至少阅读一个与当前工作直接相关的源码、配置或测试文件；只阅读 README、需求文本或工作项描述不算完成代码检查。
- 沿真实调用链核对 UI、API、服务、模型、迁移和测试中的相关部分，不要只凭文件名或工单标题判断。
- 能从代码、配置、测试或 AgentBoard MCP 上下文直接查明的事实，不得再向用户提问。
- `inspected_files` 不得编造。Worker 会校验路径必须位于当前项目内、文件必须真实存在，并且至少包含一个源码、配置或测试文件。

## 3. AgentBoard MCP 使用要求

- 只使用当前会话已经配置的 AgentBoard MCP 连接，不索取、打印或传递 Token。
- 开始工作前读取工作项详情、父级 Story/Epic/Proposal 规格、历史评论和已有评审结论；可用工具名以当前 MCP 工具发现结果为准。
- Review 必须先获取完整 review context，核对当前代码和测试证据后再 approve/reject。
- Dev/返工必须在理解现有实现后修改，并通过 MCP 留下真实进展、验证和剩余风险。
- QA 必须检查实现与验收标准，执行可复现验证，再给出 PASS/FAIL；只看代码或只跑健康检查都不构成业务验收。
- 如果 AgentBoard MCP 不可用、项目映射缺失或无法读取代码，应明确返回 `action=fail`，不得假装已检查或继续回写成功结果。

## 4. 各工作类型的最低要求

### Proposal Clarify

先定位相关实现和现有接口。只询问无法从代码、配置、测试、历史问答或 MCP 工作项上下文确定的产品取舍与业务决策。

### Design / Dev

先读现有架构和目标调用链，保留无关改动；实现后运行针对性测试，并报告修改文件、测试命令、结果和未覆盖风险。

### QA

先读验收标准、实现和现有测试，再执行真实验证。失败结论必须包含复现步骤和可定位证据。

### Review

先读规格、变更实现、调用链和测试。每条 finding 必须能定位到真实文件和事实；不能仅凭摘要、diff 标题或主观偏好驳回。

## 5. 失败优先

缺少代码证据、MCP 上下文、必要权限或验证条件时，宁可 fail/blocked，也不能产出看似完整但未经检查的结果。
